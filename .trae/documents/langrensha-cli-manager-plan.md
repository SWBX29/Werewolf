# 狼人杀项目管理工具 - CLI 版本实现计划

## 概述

创建一个基于命令行的交互式项目管理工具，用户可以双击运行 `.exe` 文件，通过菜单选择启动、关闭、重启项目，修改环境变量，并查看启动后的端口和网页信息。

## 当前状态分析

### 项目结构
- **项目根目录**: `e:\GitHub\langrensha`
- **工作区结构**: npm workspaces（shared、server、client）
- **启动命令**: `npm run dev`（同时启动客户端和服务端）
- **端口配置**:
  - 服务端 WebSocket: `PORT`（默认 3001）
  - 前端 Vite: `VITE_PORT`（默认 5180）
- **mefrpc 位置**: `server/bin/mefrpc.exe`
- **环境变量文件**: `.env`（从 `.env.example` 复制）

### 环境变量列表
根据 `.env.example` 分析，需要管理的环境变量：
1. `PORT` - 服务端端口（默认 3001）
2. `VITE_PORT` - 前端端口（默认 5180）
3. `MONGODB_URI` - MongoDB 连接字符串
4. `ADMIN_SECRET` - 管理员密钥
5. `ZEGO_APP_ID` - Zego App ID
6. `ZEGO_SERVER_SECRET` - Zego Server Secret
7. `MEFRP_ARGS` - ME Frp 启动参数（可选）

### mefrpc 管理策略
根据用户需求"mefrp核心程序启动后不能关闭，需要常驻开启"：
- 项目启动时，如果 `MEFRP_ARGS` 有配置，则启动 mefrpc
- mefrpc 启动后作为独立进程常驻运行
- 项目关闭时，**不关闭** mefrpc（保持常驻）
- 管理工具提供单独的 mefrpc 启动/停止按钮

## 功能详细说明

### 启动项目
1. 检查 `.env` 文件是否存在，不存在则从 `.env.example` 复制
2. 检查端口 3001 和 5180 是否被占用
3. 如果被占用，显示占用进程信息，询问是否终止
4. 执行 `npm run dev` 启动项目
5. 如果 `MEFRP_ARGS` 有配置，启动 mefrpc
6. 显示启动成功信息和访问地址

### 关闭项目
1. 查找 node/npm/vite 相关进程
2. 终止这些进程
3. **不终止 mefrpc**（保持常驻运行）
4. 显示关闭成功信息

### 重启项目
1. 执行关闭项目流程
2. 等待 2 秒
3. 执行启动项目流程

### 修改环境变量
1. 显示当前所有环境变量
2. 用户选择要修改的变量
3. 输入新值
4. 保存到 `.env` 文件
5. 提示是否需要重启项目使配置生效

### ME Frp 单独管理
- **启动**: 检查 `MEFRP_ARGS` 配置，启动 mefrpc 进程
- **停止**: 终止 mefrpc 进程（用户主动操作）

### 查看日志
- 显示最近的启动日志
- 显示进程状态

## 界面设计

使用 `rich` 库实现：
- **表格**: 显示环境变量列表
- **面板**: 显示项目状态
- **进度条**: 启动/关闭过程
- **颜色**: 状态指示（绿色=运行，红色=停止，黄色=警告）
- **实时刷新**: 状态变化时自动更新显示

## 验证步骤

1. **双击运行测试**: 确认 `.exe` 可以直接双击打开
2. **启动功能测试**: 确认项目可以正常启动，端口正确显示
3. **关闭功能测试**: 确认项目进程被终止，mefrpc 保持运行
4. **重启功能测试**: 确认重启流程正常
5. **环境变量修改测试**: 确认可以正确读取和写入 `.env`
6. **mefrpc 管理测试**: 确认单独启动/停止功能正常
7. **端口冲突处理测试**: 确认端口被占用时能正确提示和处理

## 注意事项

1. **进程识别**: 需要准确识别项目进程，避免误杀其他进程
2. **端口检查**: 使用 `netstat` 或 `psutil` 检查端口占用
3. **mefrpc 常驻**: mefrpc 启动后独立运行，不随项目关闭
4. **错误处理**: 提供清晰的错误提示和解决方案
5. **日志输出**: 启动过程中显示关键日志信息
6. **配置验证**: 启动前验证必要的环境变量是否配置
